# Input, part 2 (sub-project 3b) Implementation Plan

> **For agentic workers:** work task by task; test first (see it fail, then pass), then typecheck, tests and
> `npm run build -w @pv/web` after each task; commit with explicit paths. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A member can move transactions in and out as CSV (with a preview that validates every row before
anything is stored), change their name, language, base currency and time zone, and delete their account. An
admin can invite people to a self-hosted instance with a one-time link and manage members.

**Architecture:** Parsing and row validation are pure functions in `packages/core` (`csv.ts`,
`import-rows.ts`). Security resolution and the all-or-nothing import live in `packages/db` (`imports.ts`),
reusing the ledger replay of `transactions.ts` under the portfolio row lock. The web app adds `/import`
(upload → preview → confirm, server actions), `GET /api/export` (CSV download), `/settings`, `/admin` and
`/invite/[token]`. Invite tokens are 32 random bytes, stored as SHA-256, single use, valid 7 days.

**Spec:** `docs/superpowers/specs/2026-09-26-portfolio-viewer-design.md` §3 (access, invites), §7 (`/import`,
`/settings`, `/admin`, CSV columns), §10. Carried items from `docs/STATUS.md`: block base-currency changes
once transactions exist; one-time invite links for self-hosting.

## Global Constraints

- As in 3a: English in the repository, German only in `de.json`; every string in both message files;
  writes call `requireMember()` / `requireAdmin()` first; repository functions take the member id.
- CSV columns (spec §7): `date, portfolio, type, isin, symbol, exchange, quantity, price, currency, fees,
  taxes, amount, note`, plus two optional columns `fx_rate` and `split_ratio` (needed for foreign-currency
  rows without a reference rate and for splits). Header names are case-insensitive; column order is free.
- Import accepts `,` and `;` as delimiter (German Excel writes `;`). Numbers follow the delimiter:
  `;` → German decimals (`1.234,56`), `,` → English. Dates `YYYY-MM-DD` or `DD.MM.YYYY`.
- Types in CSV: `buy, sell, dividend, transfer_in, transfer_out, split`. Mergers (`exchange`) are not
  importable in 3b; such rows are reported as errors ("record mergers in the app").
- Import is all or nothing: one invalid row → nothing is stored. Rows are applied in ledger order, so a
  file may list a sell before its buy.
- Export writes the same format (`,`, English numbers, ISO dates), so an export can be imported again.
- An import larger than 5,000 rows or 2 MB is refused.

## Review Focus

- A German CSV (`;`, `1.234,56`, `05.01.2026`) and an English CSV of the same trades store identical
  transactions → Task 2.
- A file whose sell exceeds the holding stores nothing and names the row → Task 3.
- An exported file imported into an empty portfolio reproduces every transaction → Task 4.
- Changing the base currency is refused once any transaction exists → Task 5.
- An invite link works once, for 7 days; a used or expired link, or a token of another instance, gives
  "invalid invite"; a normal member cannot open `/admin` or call its actions → Tasks 6 and 7.
- Deleting the account removes the member's portfolios and transactions, never shared market data → Task 5.

### Task 2: Row validation (`packages/core/src/import-rows.ts`)

**Interfaces:**
```ts
export interface ImportRow {
  line: number                // 1-based line in the file (header = 1)
  date: string; portfolio: string; type: 'buy' | 'sell' | 'dividend' | 'transfer_in' | 'transfer_out' | 'split'
  isin: string | null; symbol: string | null; exchange: string | null   // exchange = MIC
  quantity: number | null; price: number | null; currency: string; fees: number; taxes: number
  amount: number | null; fxRate: number | null; splitRatio: number | null; note: string | null
}
export interface RowIssue { line: number; column: string | null; code: 'missing_column' | 'required' | 'number' | 'date' | 'type' | 'security' | 'currency' | 'not_allowed' | 'too_many_rows' }
export function readImportRows(csv: ReturnType<typeof parseCsv>): { rows: ImportRow[]; issues: RowIssue[] }
```
Rules: required columns `date, portfolio, type, currency`; a security needs `isin` or `symbol`+`exchange`;
per type the same required fields as the transaction form (buy/sell/transfer_in: quantity + price;
transfer_out: quantity; dividend: amount; split: split_ratio); fees/taxes only on buy/sell/dividend
(`not_allowed` otherwise, spec §5); currency 3 upper-case letters; ISIN format check (12 chars, checksum);
more than 5,000 rows → `too_many_rows`.

- [ ] Tests: the same three trades as German CSV and English CSV give equal `rows`; `12,5` in a `;` file
      is 12.5, `1.000` is 1000; `05.01.2026` → `2026-01-05`; missing price on a buy → `required` with
      line and column; fee on a split → `not_allowed`; `exchange` type → `type`; bad ISIN checksum →
      `security`; unknown column is ignored.
- [ ] Implement (use `parseDecimalInput`), commit `feat(core): validate CSV import rows`.

### Task 3: Import into the database (`packages/db/src/imports.ts`)

**Interfaces:**
```ts
export interface ResolvedSecurity { instrumentId: string; listingId: string; name: string; currency: string }
export type SecurityResolver = (row: ImportRow) => Promise<ResolvedSecurity | null>
export interface ImportPlan {
  rows: (ImportRow & { security: ResolvedSecurity | null; portfolioId: string | null })[]
  newPortfolios: string[]           // names that will be created
  issues: RowIssue[]                // Task 2 issues + 'security' (not found) + 'oversell' + 'fx_missing' + 'duplicate' (warning only)
}
export function planImport(db, memberId, rows: ImportRow[], resolve: SecurityResolver): Promise<ImportPlan>
export function applyImport(db, memberId, plan: ImportPlan): Promise<{ transactions: number; portfolios: number }>
export function defaultSecurityResolver(db, provider: MarketDataProvider | null): SecurityResolver
```
- `planImport` matches portfolios by name (case-insensitive, the member's non-archived ones), resolves each
  distinct security once, dry-runs the ledger per portfolio (existing transactions + new rows) to report
  `oversell` with the line, resolves missing FX rates (`fx_missing` with line), and flags rows identical to
  a stored transaction (same portfolio, security, date, type, quantity, price/amount) as `duplicate`
  warnings.
- `applyImport` re-plans inside one database transaction (holding the portfolio row locks), refuses when
  any error-level issue exists, creates missing portfolios, inserts with `source = 'import'`.
- Resolver: ISIN → `instruments.isin`; else `exchange`+`symbol` → listing; else the provider
  (`describe({ mic, symbol })`, or `search(isin)` with exactly one hit) → `upsertListing`; else null.
- [ ] Tests `packages/db/test/imports.test.ts` (Testcontainers): happy path creates a portfolio and three
      transactions with `source = 'import'`; a sell before its buy in the file is accepted; an oversell
      stores nothing and reports the line; a row with an unknown security reports `security`; another
      member's portfolio with the same name is not used (a new one is created for this member);
      duplicate warning does not block; concurrent `applyImport` + `createTransaction` never leave an
      oversold ledger.
- [ ] Implement, commit `feat(db): plan and apply CSV imports`.

### Task 4: `/import` page and CSV export

- `app/import/page.tsx` (server) with a client `ImportForm`: file input (`.csv`, 2 MB), portfolio hint,
  link to download a template (`/api/export?template=1`).
- Server action `previewImport(formData)` → `{ plan }` serialisable (rows with status, issues with
  translated messages keyed `import.err_<code>`), shown as a table: line, date, portfolio, type, security
  (resolved name or "not found"), quantity, price/amount, status. Errors listed first; "Import N
  transactions" disabled while errors exist.
- `confirmImport(token)`: the preview stores the parsed rows server-side for 15 minutes under a random
  token bound to the member (table `import_drafts`: id, member_id, rows jsonb, created_at; purged on read
  and by age) — the client never sends rows back, so the preview cannot be tampered with.
- `GET /api/export` → `text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="portfolio-viewer-YYYY-MM-DD.csv"`,
  all transactions of the member's portfolios (archived included). Merger legs are exported as rows of
  type `exchange_out` / `exchange_in` with an extra `link` column, so the export is complete; the importer
  reports them as `type` errors until mergers become importable.
- Home page and portfolio menu get links "Import" and "Export".
- [ ] Tests: `apps/web/test/export.test.ts` (pure `transactionsToCsv`), e2e `03-import.spec.ts`: upload a
      German CSV with 3 rows (one new portfolio), see the preview, confirm, see the positions; upload a
      file with an oversell, see the error with its line and nothing stored; export and compare row count.
- [ ] Commit `feat(web): CSV import with preview, CSV export`.

### Task 5: Settings (`/settings`)

**Interfaces (db):** `updateMemberSettings(db, memberId, { displayName?, locale?, baseCurrency?, timezone? })`
— validates (`locale` in en/de; `baseCurrency` in the currencies the app can convert, see
`packages/core/src/currency.ts`; `timezone` in `Intl.supportedValuesOf('timeZone')`); a base-currency
change when the member has any transaction → `ValidationError` path `baseCurrency`, reason `has_transactions`.
`deleteMember(db, memberId)` — refuses for the last active admin; deletes the member (portfolios,
transactions, dismissed splits cascade).

- Page: name, language (sets `members.locale` and the locale cookie; the app's locale order becomes
  member setting → cookie → Accept-Language), base currency (select disabled with an explanation once
  transactions exist), time zone (select, default from the browser on first visit), "Export all data"
  link, "Delete account" (type your e-mail to confirm) → deletes the member, then the auth user through
  GoTrue's admin API (`DELETE /admin/users/{id}` with a service-role token minted from `AUTH_JWT_SECRET`;
  hosted: `AUTH_SERVICE_ROLE_KEY`), signs out.
- Shell nav gets "Settings"; admins also "Admin".
- [ ] Tests (db): base currency change refused with a transaction, allowed without; invalid time zone
      refused; last admin cannot delete themselves; deleting a member leaves instruments and prices;

### Task 6: Invites in the database

**Schema:** `invites` (id uuid, token_hash text unique, member_id uuid → members on delete cascade,
created_by uuid → members, created_at, expires_at, used_at).

**Interfaces:** `requireAdminMember(member)` helper; `createInvite(db, adminId, email): Promise<{ token: string; memberId: string }>`

(hash lookup, unused, not expired, member row still without `userId` → link `userId`, set status

`setMemberStatus(db, adminId, memberId, 'active' | 'disabled')` (not for oneself); `removeMember(db, adminId, memberId)`
(not oneself, not the last admin); `revokeInvite(db, adminId, memberId)`.
- [ ] Tests: token works once (second claim → invalid); expired token invalid; token of a revoked invite
